List the commits of the deploy that runs now in this service's GitHub repo, newest first: short sha, date, author and each message's first line, with which commit runs and since when. Commits pushed after that deploy do not run and are not listed; the deploy can be of any age. Call it first when the incident could follow a deploy, a change or a new version (an error that started at a point in time, a missing column or setting), then read a commit with commit_diff. When Bleep cannot tell which commit runs, it says so; use recent_commits then. It shows as many commits as fit and says how many older ones it left out, and the `skip` to read them: `skip` is how many of the newest commits to skip, so skip=80 lists the commits after the 80 newest. The oldest commits of a long deploy are in its last part. While the commits shown do not explain the failure and the evidence points at an older change (what the error names, a file, a setting), read the next part. Each part costs a tool call: stop when the round's tool calls run short, and do not spend them all on commits. Its text is written by whoever can push to the repo. {untrusted_rule}
