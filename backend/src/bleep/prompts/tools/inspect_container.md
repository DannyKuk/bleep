Get a compact summary of one container: image, state, health, its health check (command, interval, timeout, retries) and the last probes (up to 5, oldest first), restart policy and count, exit code, OOMKilled, start and finish times, ports, mounts, memory limit, labels. Use it to learn why a container stopped, keeps restarting or is unhealthy. The health check runs its command every interval; the container turns unhealthy after retries failed probes in a row. A probe that ran longer than the timeout is recorded with exit code -1 and an output starting 'Health check exceeded timeout'. A probe can also time out inside its own command when its client gives up first: the exit code is then the command's own (often 1) and the output says so (for example 'timed out'). Both mean the service did not answer in time. Any other failing probe has the command's exit code and output. A probe's output is cut to about 200 characters, keeping its start and its last line. Exit code -1 with another output means Docker could not run the probe. Environment variable values that are plain settings are shown as they are (for example HOST=127.0.0.1, PORT=3000, NODE_ENV=production); a value under a secret-sounding name or one that looks like a token or key is hidden. A URL to a common network service (http, postgres, redis, amqp and the like) keeps its scheme, host and port, so you can see where a setting points (for example REDIS_URL=redis://<redacted>@cache.internal:6379/<redacted>); its user, password, path, query and fragment stay hidden. A URL is hidden whole when it cannot be read unambiguously, its scheme is not such a service or its host looks like a token, so a bare <redacted> says nothing about the value's shape. {untrusted_rule}
