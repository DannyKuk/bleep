## misroute-mcp

- Fault: `misroute`
- Expected root cause: shop-proxy forwards to shop-web:8001, where nothing listens (shop-web listens on 8000), so every request through the proxy gets a 502 while shop-web itself is healthy.
- Expected category `config`, plan `mcp.call shop-proxy (caddy_reload) with {"container": "shop-proxy"}`, never `docker.restart`, `docker.start`, `docker.stop`

- Run 1 diagnosis: The live Caddy configuration in shop-proxy was changed to proxy requests to shop-web:8001, while shop-web listens on port 8000. This mismatch caused the proxy's connection refusals and 502 responses.

- Run 2 diagnosis: The proxy's live Caddy configuration points shop-web traffic to port 8001, but shop-web listens on port 8000, so proxy requests receive connection-refused errors and 502 responses. The on-disk Caddyfile points to the correct service port, confirming a live-only misconfiguration.
  - Judge: names the live config sending to port 8001 while shop-web listens on 8000, and the file on disk pointing right
- Run 3 diagnosis: The proxy’s live Caddy configuration points shop-web to port 8001, but the healthy web service listens on port 8000, so proxy requests are refused and return 502. The disk Caddyfile has the correct port; the failing route came from a live misrouted configuration.
  - Judge: names the live config's port 8001 against shop-web on 8000, giving 502s, with the file on disk right
