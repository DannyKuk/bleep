## Why this round

#497 adds `skip` to `deployed_commits`, changes the tool's description and the cut note ("call deployed_commits with skip=K for them"), and adds `bad-deploy-long`: a 300-commit deploy, 41 days old, with 24 commits pushed after it, whose oldest commit is the one that reads `price_cents`. The bad-deploy scenarios are the faults a commit causes, and the commit attacks read commit text through the GitHub tools, so both check the changed description, as for #351 ([deployed-commits-2026-11-12](deployed-commits-2026-11-12.md)).

## What it shows

- **The new wording did no harm.** Every scenario run kept the root cause and the exact plan, as in the #351 round, and the two commit attacks passed as before. The description now tells the model to read the next part while the evidence points at an older change and to stop when its tool calls run short; nothing in these runs read commits past what the diagnosis used.
- **The model follows the cut note when it reads on.** The one further read was `skip=112`, the number the note printed, so a model that pages lands on the next commits, with no gap or repeat.
- **`bad-deploy-long` does not test paging to the cause.** The deploy's newest commit is the one that switches `SHOP_VERSION` to 2, and the shop-web and shop-db logs Gather reads before the model starts name the missing `price_cents` column (every diagnosis cites them), so all three runs diagnosed the fault from the first part and those logs. The oldest commit is evidence the judge does not ask for; in `bad-deploy-old`, where it is in the first part, the model named it every time. Whether a model pages to an old cause when only an old commit explains the fault needs a scenario whose deploy's newest commits do not.
- **Every run spent all 8 tool calls.** A further part costs one of them, which is why the description ties reading on to the calls left.

## Limits

- One model, 3 runs a scenario.
- The GitHub answers are the fixture's (`evals/fixtures/github/bad-deploy-long.json`, generated by `evals/long_deploy.py`), served by `evals.github.fixture_client`, which pages as the recorded answers in `tests/fixtures/github/` show GitHub does; no run read GitHub itself.
- The raw scenario file keeps each tool call's arguments cut short, which is enough to see `skip`.
