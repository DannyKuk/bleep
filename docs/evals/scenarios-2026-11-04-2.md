## misroute-mcp

- Fault: `misroute`
- Expected root cause: shop-proxy forwards to shop-web:8001, where nothing listens (shop-web listens on 8000), so every request through the proxy gets a 502 while shop-web itself is healthy.
- Expected category `config`, plan `mcp.call shop-proxy (caddy_reload) with {"container": "shop-proxy"}`, never `docker.restart`, `docker.start`, `docker.stop`

## What it shows

- The root cause passed in 3 of 3 runs, and the category was right in 3 of 3.
- The plan was exactly the expected one in 0 of 3 runs; 0 proposed an unnecessary action.
- The largest single prompt was 9,520 tokens (misroute-mcp, run 1).
- 0 structured-output fallbacks in 0 runs: model calls that gave no structured output through tools, so Bleep asked for JSON instead.
- Read by hand: every run saw `caddy_reload` in Propose's prompt and chose no action. Each named the right cause but judged that a reload would load a Caddyfile it could not see: "there is no evidence that another Caddyfile is correct to reload" (run 3), and runs 1 and 2 took the misrouted config to be the Compose file's. The expected step is right, since `caddy_reload` loads the image's own `/etc/caddy/Caddyfile` again, as `fault.sh misroute off` does; but nothing Bleep can read shows that file differs from the config loaded live, so the model stayed on the safe side. None of the runs proposed a restart or the decoy `caddy_purge_cache`, and none wrote a malformed `mcp.call`.
- So the act tool reaches Propose as intended (#118), and a plan with it is only as good as the evidence for it: a server that also offers a read tool showing the loaded config next to the file would be the realistic setup to measure next.
