# Agent

How Bleep talks to a model, counts what it spends and copes with weak models.

- **One factory, three providers.** `chat_model(settings, role)` returns `ChatOpenRouter` for `openrouter`, `ChatOpenAI` pointed at `LOCAL_BASE_URL` for `local` and `ChatAnthropic` (`langchain-anthropic`) for `anthropic`; the `main` and `cheap` roles pick the model id. Reason: Ollama and LM Studio speak the OpenAI protocol, and Claude through the Anthropic API directly needs no router; switching provider is one env var and the graph never knows which it has (#12, #504).
- **The model ids default per provider, in one place: `ModelSettings.resolved()`.** With `anthropic`, an id equal to the OpenRouter default (`openai/gpt-6-luna`) becomes `claude-haiku-5-5`, for the main and the cheap model alike; any other id stays, and `openrouter` and `local` get what they always did. `SettingsStore.models()` and `chat_model()` both call it, so `LLM_PROVIDER=anthropic` with only the key, and "Anthropic" chosen on the Settings page without editing the id fields, end up with the Claude ids, and the page shows them. Unset is told from typed by value, not by whether a field was set: the OpenRouter default is not an Anthropic id, so an id equal to it can only be one nobody chose for Claude (a person who types exactly that id for Anthropic gets Claude's too). Reason: otherwise the OpenRouter default goes to Anthropic, gets a 404 (not transient), and `invoke_structured` spends a second call on it first because `NotFoundError` is in `TOOLS_REJECTED` (#504). The main default was `claude-sonnet-5-5` until #525: one incident on it on 2026-11-12 cost $0.37 in 7 calls and ran past the 150,000-token incident cap before it could propose, against under a cent for the same kind of look on `openai/gpt-6-luna`. Claude Haiku 5.5 is priced like gpt-6-luna; how well it diagnoses is not measured yet (#515). Sonnet and Opus stay one typed id away.
- **The Anthropic branch sets no temperature and a `max_tokens` of 16,000.** Claude Sonnet 5.5 refuses any temperature but its default (`langchain-anthropic` raises on it), so `ModelSettings.temperature` is not passed. `ChatAnthropic` would otherwise send the model's own output limit (128,000) as `max_tokens`, far above what Bleep's short replies need and enough for a runaway reply to run up the bill. Thinking tokens count against the cap. Timeouts and retries are as for the other two: seconds, `CLIENT_MARGIN_S` over the guard's, no client retries. Structured output works through LangChain's standard `with_structured_output`; Sonnet 5.5 does not take a forced tool choice, so `langchain-anthropic` leaves it out, and a reply without the tool call ends in the plain-JSON fallback below (#504).
- **Cost comes from OpenRouter first.** `langchain-openrouter` copies the `usage.cost` of each response into `response_metadata["cost"]`, and `UsageTracker` records that. Without it a small price table is used (local models are free), and an unknown cloud model records tokens with no cost and one warning. The Anthropic API reports no cost, so the Claude models are in that table, at the prices on Anthropic's pricing page (Claude Sonnet 5.5 $2 / $10, Claude Haiku 5.5 $0.10 / $0.50 and Claude Opus 5.5 $4 / $20 per million input / output tokens, read 2026-11-12); Haiku 5.5 charges $0.50 / $2.50 for a call whose prompt is over 100,000 tokens, which the table has too, and an id with a date suffix is priced as its alias. Reason: the provider's own number is exact and needs no price list to keep current, but where there is none the cap must still count (#12, #504).
- **Only the investigate loop caches the repeated prompt on Anthropic, and the ledger prices cache reads and writes apart.** `cached(model)` in `llm/factory.py` returns a `ChatAnthropic` with `model_kwargs={"cache_control": {"type": "ephemeral"}}` (any other model comes back as it is), and `investigate` is the one caller, so a model from `chat_model()` sends no `cache_control`. The kwarg goes out as as the Messages API's top-level automatic caching: the API puts one breakpoint on the last cacheable block of each request, so tools, system prompt and every earlier message (tool results included) are read back from the cache on the next call of the same run, and the breakpoint moves forward as the history grows. Entries live 5 minutes and every read refreshes them; a prefix under the model's minimum cacheable size just does not cache. OpenRouter and local models are not touched. Which calls cache, and why: only the investigate loop sends a prefix again, so its calls 2 and later read the earlier ones and a second round reads the first. Diagnose, propose and report (each one structured call), a chat answer in `talk` and the watcher's explain are one-shot, so a write would be paid for and never read (#546). Nothing in the prefix changes between the calls of a run: the system prompt is one fixed file, the tool list is bound once per round in registry order, and the one timestamp and the untrusted-wrapper ids live in messages that are stored once and replayed as they were (`tests/graph/test_investigate_prefix.py`); a second round replays the first's messages unchanged. `langchain-anthropic` reports `input_tokens` as plain plus cache read plus cache write, so `usage.tokens_in` stays every input token and migration 0029 adds `cache_read_tokens` and `cache_write_tokens` as parts of it (0 for older rows; `_cache_tokens` reads whatever `input_token_details` a provider's LangChain client reports, so OpenRouter and local rows can hold cache tokens too, where the server reports cached prompt tokens, but their cost is unchanged: OpenRouter's own `cost` is taken as given and a priced non-Claude model has no entry in `CACHE_RATES`, so its cache tokens cost as plain input); sums over `tokens_in`, `by_incident` and `by_day` read as before. `_cost` prices the plain part at the input price, a read at 5% of it on Sonnet 5.5 and Opus 5.5 and 10% on Haiku 5.5, and a write at 125% (the 5-minute rate; Bleep never asks for the 1-hour entry), from Anthropic's pricing page read 2026-11-13; Haiku 5.5's long-prompt threshold counts reads and writes in the prompt size, as the page says. **Cache reads count in full against `Budgets.incident_tokens`**: the cap is a guard against a runaway loop, calibrated in #527 against whole prompts, and a call that re-reads a 20,000-token prefix is as much a loop turn as one that sent it fresh; discounting reads would silently lift that guard several times over, while the dollar caps already follow the cheaper price. The one cost: the premium is paid for any prefix that is not sent again within 5 minutes. Reason for caching investigate: an incident on Claude Sonnet 5.5 sent 156,562 input tokens in 7 calls, $0.31 of its $0.37, nearly all of it the same prefix resent (#529). Reason for caching nothing else: the first run with `cache_control` on every call wrote 70,359 tokens for the one-shot calls and never read them back, $0.035 of a $0.333 incident on Sonnet 5.5 (`docs/evals/anthropic-cache-2026-11-13.md`), so without those writes it would have cost about $0.298 (#546). That saving follows from the measured rows; the next Claude round (#515) will show it.
- **On the Anthropic provider, structured output goes through Claude's `json_schema` method.** `invoke_structured` calls `with_structured_output(schema, method="json_schema")` when the model is a `ChatAnthropic`, which sends the schema as `output_config.format` and parses the reply text, instead of binding the schema as a tool. OpenRouter and local models keep the tool method, and the plain-JSON fallback stays the safety net for any model whose structured reply is rejected or does not parse. Reason: Claude Sonnet 5.5 does not take a forced tool choice, so `langchain-anthropic` bound the tool unforced and warned about it, Claude answered in prose without calling it, and the diagnose node paid for a second call through the fallback: 2 of 3 structured calls on a live run (`docs/evals/anthropic-cache-2026-11-13.md`). A request-body test shows one call and no tool (#515). The paid scenario round that confirms the fallback no longer fires on a real incident is still to come.
- **A ledger in SQLite with a daily cap.** Every call is a row in `usage`; `check_budget` raises `BudgetExceeded` before a call when the day's spend passes $1.00 or an incident passes 300k tokens. Days are the machine's local date. Reason: the cap has to survive restarts and stop a runaway loop before the next call, not after it (#12). The incident cap was 150k until #527. That fit `openai/gpt-6-luna` (38 incidents averaged 49k tokens, the largest 105k), but Claude counts the same text as about 1.5× the tokens (an incident's first call: 9,910 on gpt-6-luna, 14,853 on Claude Sonnet 5.5), and an incident on Sonnet stopped at 162k in 7 calls before it could propose. The dollar cap still bounds the spend: 300k tokens on Claude Haiku 5.5 is about $0.03.
- **An incident's tokens and cost are read from the ledger, not stored on the incident.** `IncidentRepo` sums the `usage` rows of the incident when it reads it, so `incident.tokens` and `cost_usd` match `incident_total` for every provider; the cost is empty when no call has a known price. A call's reasoning tokens count when a server reports more of them than its completion tokens, since they then cannot be part of that number. Reason: the `tokens` column was never written, so it stayed 0 although the ledger recorded every call, local ones included (#102); migration 0025 dropped the unused `incidents.tokens` and `incidents.cost_usd` columns, and `_COLUMNS` keeps the two names as aliases of the sums (#248).
- **Structured output falls back to plain JSON.** `invoke_structured` tries tool-based `with_structured_output`; on a parse error, a missing tool API or a bad reply it asks for JSON in plain text (`prompts/llm/json_fallback.md`), validates it with pydantic and retries once with the error. Then it raises `StructuredOutputFailed` with the truncated reply. Reason: small local models often cannot call tools reliably, and Bleep must degrade rather than stop (#12).
- **Each fallback is logged once** (`FALLBACK` on `bleep.llm.structured`), and the evals count those lines per run. Reason: how often a model needs the fallback is part of choosing it; gpt-oss-20b on LM Studio needed it in 0 of 45 runs ([chat model](../decisions/chat-model.md)) (#35).
- **The defaults are `openai/gpt-6-luna` for both cloud roles and `openai/gpt-oss-20b` locally.** Reason: measured against each other, and against an earlier local model (the Qwen round in [chat model](../decisions/chat-model.md)); the local model is as accurate on the demo faults but never says unsure and acts more, so it is recommended with that caveat ([chat model](../decisions/chat-model.md)) (#35).
- **`FakeChatModel` is a real `BaseChatModel`.** It replays scripted `AIMessage`s with tool calls and usage, and runs out loudly. Reason: graph tests can drive it through `bind_tools` and `with_structured_output` with no network (#12). The Gather tests also use it to prove that Gather never calls a model (#16).
- **A model call is wrapped by `ModelGuard`: a timeout, retries, and a pause when the model stays down.** Which errors count as an outage includes the `anthropic` SDK's connection, timeout, rate-limit and 5xx errors (529 overloaded among them); its HTTP layer is `httpx2`, so none of them is an `httpx` error and they are listed by type (#504). The behaviour and its budgets are in [incidents](incidents.md#model-outages-and-stuck-incidents). Reason: a model outage must pause an incident, not fail it (#86).
