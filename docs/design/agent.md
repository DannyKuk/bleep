# Agent

How Bleep talks to a model, counts what it spends and copes with weak models.

- **One factory, three providers.** `chat_model(settings, role)` returns `ChatOpenRouter` for `openrouter`, `ChatOpenAI` pointed at `LOCAL_BASE_URL` for `local` and `ChatAnthropic` (`langchain-anthropic`) for `anthropic`; the `main` and `cheap` roles pick the model id. Reason: Ollama and LM Studio speak the OpenAI protocol, and Claude through the Anthropic API directly needs no router; switching provider is one env var and the graph never knows which it has (#12, #504).
- **The model ids default per provider, in one place: `ModelSettings.resolved()`.** With `anthropic`, an id equal to the OpenRouter default (`openai/gpt-6-luna`) becomes `claude-sonnet-5-5` (main) or `claude-haiku-5-5` (cheap); any other id stays, and `openrouter` and `local` get what they always did. `SettingsStore.models()` and `chat_model()` both call it, so `LLM_PROVIDER=anthropic` with only the key, and "Anthropic" chosen on the Settings page without editing the id fields, end up with the Claude ids, and the page shows them. Unset is told from typed by value, not by whether a field was set: the OpenRouter default is not an Anthropic id, so an id equal to it can only be one nobody chose for Claude (a person who types exactly that id for Anthropic gets Claude's too). Reason: otherwise the OpenRouter default goes to Anthropic, gets a 404 (not transient), and `invoke_structured` spends a second call on it first because `NotFoundError` is in `TOOLS_REJECTED` (#504).
- **The Anthropic branch sets no temperature and a `max_tokens` of 16,000.** Claude Sonnet 5.5 refuses any temperature but its default (`langchain-anthropic` raises on it), so `ModelSettings.temperature` is not passed. `ChatAnthropic` would otherwise send the model's own output limit (128,000) as `max_tokens`, far above what Bleep's short replies need and enough for a runaway reply to run up the bill. Thinking tokens count against the cap. Timeouts and retries are as for the other two: seconds, `CLIENT_MARGIN_S` over the guard's, no client retries. Structured output works through LangChain's standard `with_structured_output`; Sonnet 5.5 does not take a forced tool choice, so `langchain-anthropic` leaves it out, and a reply without the tool call ends in the plain-JSON fallback below (#504).
- **Cost comes from OpenRouter first.** `langchain-openrouter` copies the `usage.cost` of each response into `response_metadata["cost"]`, and `UsageTracker` records that. Without it a small price table is used (local models are free), and an unknown cloud model records tokens with no cost and one warning. The Anthropic API reports no cost, so the Claude models are in that table, at the prices on Anthropic's pricing page (Claude Sonnet 5.5 $2 / $10 and Claude Haiku 5.5 $0.10 / $0.50 per million input / output tokens, read 2026-11-12); Haiku 5.5 charges $0.50 / $2.50 for a call whose prompt is over 100,000 tokens, which the table has too, and an id with a date suffix is priced as its alias. Reason: the provider's own number is exact and needs no price list to keep current, but where there is none the cap must still count (#12, #504).
- **A ledger in SQLite with a daily cap.** Every call is a row in `usage`; `check_budget` raises `BudgetExceeded` before a call when the day's spend passes $1.00 or an incident passes 150k tokens. Days are the machine's local date. Reason: the cap has to survive restarts and stop a runaway loop before the next call, not after it (#12).
- **An incident's tokens and cost are read from the ledger, not stored on the incident.** `IncidentRepo` sums the `usage` rows of the incident when it reads it, so `incident.tokens` and `cost_usd` match `incident_total` for every provider; the cost is empty when no call has a known price. A call's reasoning tokens count when a server reports more of them than its completion tokens, since they then cannot be part of that number. Reason: the `tokens` column was never written, so it stayed 0 although the ledger recorded every call, local ones included (#102); migration 0025 dropped the unused `incidents.tokens` and `incidents.cost_usd` columns, and `_COLUMNS` keeps the two names as aliases of the sums (#248).
- **Structured output falls back to plain JSON.** `invoke_structured` tries tool-based `with_structured_output`; on a parse error, a missing tool API or a bad reply it asks for JSON in plain text (`prompts/llm/json_fallback.md`), validates it with pydantic and retries once with the error. Then it raises `StructuredOutputFailed` with the truncated reply. Reason: small local models often cannot call tools reliably, and Bleep must degrade rather than stop (#12).
- **Each fallback is logged once** (`FALLBACK` on `bleep.llm.structured`), and the evals count those lines per run. Reason: how often a model needs the fallback is part of choosing it; gpt-oss-20b on LM Studio needed it in 0 of 45 runs ([chat model](../decisions/chat-model.md)) (#35).
- **The defaults are `openai/gpt-6-luna` for both cloud roles and `openai/gpt-oss-20b` locally.** Reason: measured against each other, and against an earlier local model (the Qwen round in [chat model](../decisions/chat-model.md)); the local model is as accurate on the demo faults but never says unsure and acts more, so it is recommended with that caveat ([chat model](../decisions/chat-model.md)) (#35).
- **`FakeChatModel` is a real `BaseChatModel`.** It replays scripted `AIMessage`s with tool calls and usage, and runs out loudly. Reason: graph tests can drive it through `bind_tools` and `with_structured_output` with no network (#12). The Gather tests also use it to prove that Gather never calls a model (#16).
- **A model call is wrapped by `ModelGuard`: a timeout, retries, and a pause when the model stays down.** Which errors count as an outage includes the `anthropic` SDK's connection, timeout, rate-limit and 5xx errors (529 overloaded among them); its HTTP layer is `httpx2`, so none of them is an `httpx` error and they are listed by type (#504). The behaviour and its budgets are in [incidents](incidents.md#model-outages-and-stuck-incidents). Reason: a model outage must pause an incident, not fail it (#86).
