# Memory

What Bleep remembers between incidents and how it uses it (`backend/src/bleep/memory/`, `tools/memory.py`). Short-term memory is the incident's checkpointed graph state ([graph](graph.md)); this page is about long-term memory: every finished incident, the human's decision on it, and facts per service (spec §4.7).

| Piece | Path | What it does |
|---|---|---|
| **Embedders** | `memory/embeddings.py` | `Embedder.embed(texts) -> np.ndarray`, unit-length float32 rows. `FastEmbedEmbedder` (local, the default), `OpenAICompatEmbedder` (any `/embeddings` endpoint), `FakeEmbedder` (hashed words, for tests). |
| **Store** | `memory/store.py`, migration `0010_memory.sql` | `MemoryStore`: `add_report`, `similar`, `reembed`, and `facts`, `add_fact`, `delete_fact`, in the `memory_incidents` and `service_facts` tables. |
| **Text** | `memory/text.py` | Cleans memory text before it is stored and labels it when a prompt gets it. |
| **Recall tool** | `tools/memory.py` | `recall_incidents(query)`, a read tool Investigate can call. |

## Choices

- **The local model is `BAAI/bge-small-en-v1.5` through `fastembed`, in the backend, on two CPU threads, baked into the image.** Reason: no paid service and no network at recall time; one embed costs 11 ms and 22 ms of CPU inside the image, and the image grows by 268 MB ([embeddings](../decisions/embeddings.md)) (#29).
- **The model is loaded on the first embed, not when the embedder is built.** Reason: building the app, and every test, then loads and downloads nothing, and a Bleep that has seen no incident does not carry the model's 160 MB (#29).
- **An OpenAI-compatible endpoint is the option: `EMBEDDINGS_PROVIDER=openai` with `EMBEDDINGS_BASE_URL`, `EMBEDDINGS_MODEL` and an optional `EMBEDDINGS_API_KEY`.** Bleep refuses to start with only half of it. An endpoint error is raised as `EmbedderError` with Bleep's own words (the status code or the error type), never the reply text. Reason: OpenAI, LM Studio and Ollama all serve that API, and a reply can echo the request (#29).
- **Every vector is stored with the embedder's name, and a different name re-embeds on boot.** `MemoryStore.reembed` runs in the app's lifespan right after the migrations, in batches of 64, committing each batch; until a record is re-embedded it is left out of recall. A re-embed that fails is logged and Bleep starts anyway. Reason: vectors of two models cannot be compared, and a model change must not lose the memory or stop Bleep (#29).
- **One record per incident, written by Report after the report is published and sent, and before the incident is closed.** `add_report` replaces the incident's record if there is one. A memory that fails is logged and the report goes on. Reason: a crash between remembering and closing runs Report again, and the second write must replace, not double; memory helps later runs and must never cost this one its report (#29).
- **A record keeps the date, title, cause, action taken, outcome text, the human's decision and feedback.** Its vector is made from `"<title>. Cause: <cause> Action: <action>."`. Reason: what failed, why and what was done is what makes two incidents alike; the decision is shown with the record, not searched on (#29).
- **The human's decision is kept in words with the plan and the day: "rejected docker.restart shop-web-1 on 2026-11-10".** An approval reads "approved ... on ...", an instruction "instructed on 2026-11-10: <text>". The prompt shows it as "the human rejected ...". Reason: the next similar incident must hear that the human already said no to that plan (#29).
- **`feedback` is stored with the record but nothing writes it yet.** Report passes none; thumbs up or down on a diagnosis or a proposal comes with the feedback views (#30).
- **Recall scores every record of the current model by cosine with numpy, drops those under `min_score` (0.5), and puts the same service's first, closest first within each group.** Reason: a few hosts' incidents fit in one matrix product well under a millisecond, and the same service's history is the most useful even when another service's incident scores higher. With bge-small, unrelated incidents score 0.49 to 0.80, so `k` and the order do most of the work ([embeddings](../decisions/embeddings.md)) (#29).
- **Gather asks for the top 3 with `"<service or host>: <signal kinds>"` and the service id, and adds the service's facts.** A host incident gets no facts (facts are per service). A failure of either becomes a line in `gaps` ("similar incidents: RuntimeError", "service facts: RuntimeError"). Reason: Gather never fails on what it cannot read ([graph](graph.md)) (#16, #29).
- **Facts are text per service, from a person (`human`) or a report (`report`), listed oldest first and deleted by id.** Nothing extracts facts from reports yet; that comes with the feedback views (#30). Reason: "always redeploy rather than restart for X" is a preference no embedding search would surface reliably, so a service's facts are always shown whole (#29).
- **Memory text is cleaned before it is stored.** Every field goes through the guard's `strip_control`, `redact_text` and `escape_untrusted`, is joined to one line and cut to 500 characters. Reason: a report's cause is written by a model that read logs; a stored record must not leak a secret or carry a tag that ends a wrapper (#29).
- **Memory reaches the model as Bleep's own records, trusted, except quoted text.** `describe_past` and `describe_fact` write one line each, and every stretch in double, typographic or back quotes is wrapped with the guard's `wrap_untrusted` (source `memory.quote`). Single quotes are left alone. The investigate prompt has a "Bleep's memory" section that says so and that a past cause is a lead, not proof; Diagnose labels each line as Bleep's own record. Reason: the record is Bleep's, but a model may have quoted a log line into it, and that line is still host text; apostrophes are far more common than single-quoted text (#29).
- **`recall_incidents(query)` is a read tool, offered whenever the app has a memory.** It returns at most 5 past incidents, without ranking by service (a tool has only the host), in the same one-line form. Its answer goes through Investigate's guard like every tool result and reaches the model wrapped as untrusted. Reason: the model can look further than Gather's three, in its own words; making one tool's output an exception to "every tool result is wrapped once" would weaken a rule that holds for all of them (#29).
- **Tests never load the real model.** A fixture in `tests/conftest.py` makes `FastEmbedEmbedder` refuse to load, and the app's parts in tests use `FakeEmbedder`; one test runs the real model when `BLEEP_REAL_EMBEDDINGS=1` is set. Reason: tests never touch the network (#29).
